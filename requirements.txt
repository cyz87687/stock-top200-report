# A股 TOP500 评分系统 — 依赖锁定
#
# ═══════════════════════════════════════════════════════════════════════
# P1-4（2026-11-03）：为什么必须钉版本
# ═══════════════════════════════════════════════════════════════════════
# 原 requirements.txt 的 7 个包**全部无版本约束**：
#
#     requests / beautifulsoup4 / lxml / html5lib / akshare / pandas / openai
#
# 风险不是理论上的：本项目 90% 的数据来自 akshare 的网页接口解析，
# 而 akshare 是**高频破坏性升级**的库（字段改名、返回结构变化、接口下线）。
# 一次 `pip install -U` 就可能让 fetch_top200_sina / factor_eval /
# append_klines_latest 同时静默产出错数据 —— 比报错更危险。
#
# pandas 同理：2.0 → 3.0 有大量行为变化（默认 dtype、copy-on-write、
# 部分 API 弃用）。本项目 pandas==3.0.3 已在跑，若某天环境回退到 2.x，
# 部分 groupby/apply 行为会变而**不报错**。
#
# 本文件按 **2026-11-03 实测运行环境** 钉死（Python 3.13.12）：
# 下面的版本号不是抄来的，是 importlib.metadata.version() 实读的。
#
# ═══════════════════════════════════════════════════════════════════════
# 升级纪律（要改版本必须走这三步）
# ═══════════════════════════════════════════════════════════════════════
#   1. 先在 _legacy_cmp/ 或临时 venv 里跑一遍全链，diff 出 scored 差异
#   2. 差异必须能逐项解释（哪个字段变了、为什么），不能"看起来差不多"
#   3. 改完本文件后跑 `python verify_env_lock.py`，确认环境与锁定一致
#
# 反例（真实踩过）：round116 的 volume 双口径事故 ——
#   库内 bar 的 volume 对 688 是「股」、对其余是「手」，
#   一个 vol*close 的写法让成交额差 100 倍，`min_amt=3e7` 实际成了 30 亿，
#   主板日均通过数从 1045 只掉到 61 只，而**所有脚本都不报错**。
#   依赖版本漂移造成的问题形状一模一样：静默、无声、数字还在但口径变了。
# ═══════════════════════════════════════════════════════════════════════
