## 0. 一句话结论（先给结论，后给证据）

| 问题 | 结论 | 强度 |
|---|---|---|
| Transformer 能不能预测大盘？ | **不能**。4 指数 Bonferroni 校正后 0 个显著 | 强（双实现交叉验证） |
| 现有 total 评分能优化 T+1 吗？ | **不能**。Spearman = −0.0257，**排名越高反而越差** | 强（1211 样本，12 推荐日） |

## 1. 作为量化从业者，这个项目最该改的 6 件事

按「影响 × 可落地性」排序，不按工作量排。

### P0-1　总分不该出现在「次日」语境里（最严重的口径错配）

**证据**（`recommendation_track.json`，12 个推荐日，H=1 有效 1211 条）：

| 分组 | T+1 超额均值 | 胜率 |
|---|---|---|
| Top10%（total ≥ 85.3） | **−1.28%** | 41.0% |
| Bot10%（total ≤ 66.5） | −0.76% | 41.0% |
| Spearman(total, T+1超额) | **−0.0257** | — |

**这不是「阈值没调好」，是维度错配**。v4.17 的 9 个生效维（fund .20 / size_growth .20 / tech_neg .10 / quality .10 / ep .10 / dominant .10 / growth .10 / bias60 .05 / rsi_rev .05）里，**没有一维是设计来预测次日方向的**：fund/growth 是季度频率，quality 是年报频率，size_growth 是市值结构。用季度频率的因子去解释日频收益，负相关都不奇怪。

**改法**：给每个维标注「**生效频率**」，页面按持有周期分档展示：
- 月度以上：total 全维参与
- 周级（H=5）：只用 tech_neg / bias60 / rsi_rev / ep
- 日级（H=1）：**不给 total 排序**，只给「事件/流动性提示」

这是本项目 ROI 最高的一处改动——不改模型，只改呈现口径，就能消除「85 分买次日亏钱」的体验落差。

### P0-2　「隔夜/日内」必须成为一等公民（所有日频信号都躺在隔夜段）

**证据**（`audit_round111b_t1_decompose.json`，303 截面）：13 个因子拆 `gap = open[t+1]/close[t]−1` 与 `intra = close[t+1]/open[t+1]−1`：

| 因子 | 隔夜 IC (t) | 日内 IC (t) | 符号翻转 |
|---|---|---|---|
| amp | −0.0920 (−8.95) | −0.0090 (−0.87) | 否 |
| turn_z | −0.1079 (−12.19) | **+0.0061 (+0.61)** | **是** |
| vol_ratio | −0.0968 (−12.67) | **+0.0053 (+0.65)** | **是** |
| rsi14 | −0.0909 (−9.44) | **+0.0040 (+0.38)** | **是** |
| dist_ma20 | −0.0976 (−9.24) | **+0.0072 (+0.62)** | **是** |

**符号翻转是关键**：`close→close` 的强负 IC 里，隔夜段负、日内段**微正**。散户收盘后才拿到信号，只能吃日内那段 → 那个强 IC 对他毫无用处。

**改法**：页面上任何「因子有效」的表述，必须同时标注它作用在哪一段。现在页面的 IC 展示是 `close→close` 口径，等于**系统性高估了信号的可执行性**。这一条建议单独做成一个「可执行性」开关：勾上后只显示日内段 IC。

### P0-3　把「扣费」写进所有收益数字（否则胜率都是假的）

**证据**（`audit_round111c_t1_executable.json`）：5 个可执行口径，判据 `|IC|≥0.02 且 |t|≥2.0 且 胜率≥55% 且 扣费后多空>0`：

| 口径 | 说明 | 通过因子 |
|---|---|---|
| E1 `open[t+1]→close[t+1]` | T0 代理 | **0** |
| E2 `open[t+1]→open[t+2]` | 抓一次隔夜 | **0** |
| E3 `close[t+1]→close[t+2]` | T+1 收盘买 | **0** |
| E4 `close[t]→close[t+1]` | 含隔夜，不可执行（对照） | 0 |
| E5 `close[t]→close[t+2]` | 2 日（对照） | 1（gap，但不可执行） |

E2 里 `amp` 的 t = −3.12，看着能打；扣 0.2% 双边后多空收益 **−0.13%**。**统计显著 ≠ 能赚钱**。

**改法**：页面上每一个「胜率 / 超额 / IC」旁挂成本假设（本项目已定 `COST = 0.002` 双边），并提供「毛 / 净」切换。现在只有毛收益，等于默认交易免费。

### P1-1　评级双口径要显式教育，不能靠文档（已在自测中发现误读风险）

`scored.rating` 用绝对阈值（A:419/B:1027/C:620/D:18），页面用当日截面分位（S 前 5% = 104 只、A 5%~15% = 209 只）。**这是设计，不是 bug**（分位保跨日可比）。但今天写页面自测时我自己就先误判成失败了一次——说明这个双口径对外部读者是**误解高发点**。

**改法**：评级徽标加 tooltip「本档 = 当日分位，非绝对分」，并在页面评级图例处直接写「S = 今日前 5%（104 只）」，把只数当场算出来给人看。

### P1-2　274 个 py 脚本无依赖图，日更链路是"记忆驱动"而非"契约驱动"

项目 248+ 个脚本，日更顺序靠 `.workbuddy/memory` 里的文字约定（`fetch → fresh → step2 → K线增量 → archive_fund → archive_fwd → AI → enhance → sector_mom → apply_sector → pick_pf → track → fetch_focus_list → fetch_bench → regime_model → gen_report → cp index.html`）。这个顺序里**已经踩过两次「顺序颠倒 → 静默缺失」**（`fetch_focus_list` 在 gen_report 之后跑 → 焦点池空；`fetch_bench → regime_model` 在 gen_report 之后跑 → 整块被跳过）。

**改法**：写成 `daily_pipeline.yaml`，每个 stage 声明 `outputs` 与 `requires`，跑完校验每个 output 的**日期戳**是否等于目标交易日。任一缺失 → 硬失败（不是告警）。这一条对应项目纪律第⑭条：「同一数据文件被两处独立读取，必有一处忘校验」。

### P2-1　K 线库 341 日不足以支撑任何策略结论（本轮最大硬约束）

`data/klines_long.json`：2138 只 × 341 日（2025-06-09 ~ 2026-11-02）。这个长度：

- 做 H=20 的因子检验，独立样本只有 **17 个周期**（`audit_round113b` 已算）
- 跨不了牛熊（只有一段行情），regime 结论天然不可外推
- 我今天唯一捞出的候选信号，2026H2 已衰减到 **胜率 48.9%、均值 +2.22%**（`audit_round114f`）

**改法（ROI 最高的一项基础设施投入）**：K 线库扩到 **≥1500 日（约 6 年，跨 2 轮牛熊）**。这不是"数据多一点"，而是**从"不能下结论"到"能下结论"的门槛**。具体做法：`append_klines_sina_fallback.py` 是按日增量，需另写一个 `backfill_klines_history.py` 做全量历史回补（新浪 `hq.sinajs.cn` 日线接口可回溯多年），一次投入长期受益。

### P2-2　缺一个「信号衰减监控」——今天手工发现的衰减应该自动报警

`audit_round114f` 的 V5 半年度显示：2025H2 均值 +4.50%（胜率 79.7%）→ 2026H1 +3.49%（65.3%）→ **2026H2 +2.22%（48.9%）**。单调衰减。如果这是实盘信号，它已经在死了，但项目里没有任何机制会发现这件事。

**改法**：给每个已上线的「信号/因子」建一条 `signal_health.json` 时间序列（滚动 60 日 IC + 胜率），跌破阈值（如胜率 < 52% 连续 20 日）→ 页面顶部黄条告警。这一条与现有 `regime_forecast` 的日期门禁是同一类机制，可复用。

## 2. T+1 建议：从「预测方向」改为「三段式执行纪律」

### 2.1 为什么不能给"买什么"

三条证据叠加，把 T+1 方向预测这条路封死了：

1. **total 评分零区分力**：Spearman −0.0257，Top10% 超额 −1.28%（1211 样本）
2. **日频因子 H=1 全池零通过**：`|IC|≥0.02 & |t|≥2.0 & 胜率≥55% & 净>0` 四门，13 因子 0 通过
3. **信号全在隔夜段**：13 因子里 12 个日内段 |t| < 1.7，4 个还符号翻转

### 2.2 那 T+1 还能做什么？——三层可执行建议

**第一层：不预测方向，只做「入场位置」纪律**（依据：本轮最强实证）

主板极端低开 → 日内反转这个信号（`audit_round114e/f`，8/8 + 6/6 检验通过）：

| 指标 | 数值 | 口径 |
|---|---|---|
| 信号 | 主板 `gap[t] ≤ 历史 p1`（扩展窗口，无前视） | 60 日最小历史 |
| 样本 | 188 个 / 81 个信号日 | 341 日 |
| 毛收益 | **+3.54%** | open→close |
| 按日聚类 t | **5.32**（朴素 t 7.94，虚高 1.49 倍） | cluster = 信号日 |
| Beta 中性超额 | **+2.11%**（t = 3.53） | 减当日全市场 intra 均值 |
| 扣费后净 | +3.26% | 小市值成本 0.28% |
| 剔除收盘涨停（地天板）后 | +2.99%，胜率 65.2% | 7 个地天板 |
| 逐月 | **13/13 个月为正**，最差 +0.77% | — |
| 阈值稳健 | −5%/−6%/−7%/−8% 全部为正，无孤岛 | 固定阈值对照 |

**怎么用（T+1 语境）**：手里有底仓、次日开盘遇到 −6% 级恐慌低开 → **不要在开盘杀跌**，日内反弹概率显著高于 50%。这是"不杀跌"的纪律，不是"抄底买入"的指令。

**第二层：把持有周期从 T+1 改成 T+20（若一定要用因子）**

`audit_round113` 显示 H=20 有 5 个因子名义通过，但 `audit_round113b` 三重证伪后**全部淘汰**：

| 因子 | t（原始） | **t（不重叠）** | Bonferroni 阈值 | 判定 |
|---|---|---|---|---|
| mom5 | −4.67 | −3.00 | 3.22 | 淘汰 |
| dist_ma5 | −3.71 | −1.12 | 3.22 | 淘汰 |
| dist_ma20 | −5.37 | −1.89 | 3.22 | 淘汰 |
| vol_ratio | −5.71 | −1.44 | 3.22 | 淘汰 |
| turn_z | −5.65 | −1.64 | 3.22 | 淘汰 |

**这就是「重叠窗口」的教科书级陷阱**：304 个日截面算 H=20 收益，相邻 19 个截面重叠 95%，t 值被放大 √20 ≈ 4.5 倍（实测 1.56~3.97 倍）。不重叠重估后最大只有 3.00 < 3.22。**所以「拉长持有期就能救」这个想法，本轮实证否定。**

**第三层：T+1 真正的优化空间在「成本与频率」，不在「选股」**

`audit_round113` 的成本模型：单周期（一次买+一次卖）= 佣金万三×2 + 印花税 0.05% + 滑点 0.10%×2 ≈ **0.26%**。年化成本 ≈ 0.26% × 244/H。

**这是拉长持有期唯一确定的正向作用：降交易频率，不是涨 IC**。H=1 → H=5，成本从年化 63.4% 降到 12.7%（假设满仓滚动）。这才是 T+1 改 T+5 的真实理由——不是"信号在 5 日更强"（已被证伪），而是"少交易能省下 50pp 年化"。

> ⚠️ 必须写明：这里算的是"满仓每日换手"的理论上限，实际组合换手率远低于此。但方向是对的——**换手是主要摩擦**（与 round77 结论一致）。

## 3. T0 建议：先算清成本门槛，别急着找信号

### 3.1 T0 无法用现有数据回测（这条不能含糊）

`data/klines_long.json` 只有日线。T0（日内回转）的全部信息在分钟级。用日线"回测 T0" = 拿 close 假装能择时，是造假。

`audit_round114` 的 meta 里已写死：
```
"what_this_is_not": "这不是 T0 回测。K 线库只有日线（341 日 × 2138 只），
                     无分钟数据 → T0 收益无法由此脚本产生，任何 T0 收益数字都不成立。"
```

### 3.2 但成本门槛可以算——这才是 T0 决策真正需要的

**核心公式**：`期望收益 = e·(2p−1) − c`，盈亏平衡 `p* = 0.5 + c/(2e)`
（e = 可捕获幅度，p = 方向命中率，c = 单次回转成本）

**日内实际涨跌幅度分布**（`audit_round114`，119,359 有效样本）：

| 分位 | \|intra\| = \|close/open−1\| |
|---|---|
| p10 | 0.44% |
| p25 | 1.08% |
| **p50** | **2.34%** |
| p75 | 4.41% |
| p90 | 7.18% |

**盈亏平衡命中率 p\***（按 e = 2.34% 中位数算）：

| 标的 | 单次回转成本 | p\*（e=2.34%） | p\*（e=0.44%，p10 情形） |
|---|---|---|---|
| ETF（免印花税） | 0.060% | **51.3%** | 56.9% |
| 主板大市值 | 0.160% | **53.4%** | 68.4% |
| 小市值高波动 | 0.280% | **56.0%** | 82.2% |

**这张表怎么读**：T0 的敌人不是"模型不准"，是**成本 / 幅度比**。小市值个股在低波动日（p10 = 0.44%）需要 **82.2% 命中率**才不亏——这是不可能的。所以 T0 只可能在**高波动日子 + 低成本标的（ETF）**上成立。

### 3.3 日线能证明的方向可预测性，不足以覆盖 p\*

`gap → intra` 同号率 = **0.4632**（偏离 50% 仅 3.68pp，且方向是**反转**不是延续）。加上 `audit_round111b` 日内段 13 因子零显著 → **日内方向无可用预测力**。

按 p\* 表：ETF 口径需要 51.3%，日线能证明的边缘是"反向 3.68pp"（即 p ≈ 53.7% 若做反转，但那是全样本平均，非条件于可交易场景）。**勉强够，但只剩 2.4pp 安全边际，扛不住未建模的滑点与冲击成本。**

**T0 结论**：
1. **不要用主模型做 T0**（9 维全是低频维）
2. T0 只有一条可能路径：**ETF + 高波动日 + 反向（低开反弹）**，且必须分钟线验证
3. 接入分钟线是 T0 的唯一前置条件。建议接入方案：`akshare.stock_zh_a_hist_min_em()`（1/5/15/30/60 分钟）或券商 L1 快照。至少要 **1 年 × 100 只** 才有统计意义
4. **在此之前，页面不得出现任何 T0 仓位建议**

## 4. 本轮唯一候选信号的完整披露（含 5 条不能越过的边界）

### 4.1 信号定义（可复现）

```
universe : 主板（60/00 开头），成交额 ≥ 3000 万
signal   : gap[t] = open[t]/close[t-1] - 1  ≤  hist_p1(gap[0:t])   # 扩展窗口，最少 60 日
entry    : open[t]（开盘集合竞价成交）
exit     : close[t]
filter   : gap <= -9.5% 视为开盘跌停不可成交，剔除
```

### 4.2 我自己的纠错记录（必须留在报告里）

第一版诊断脚本写错了索引：

```python
prev_ret[1:] = C[1:] / C[:-1] - 1.0   # ← 这是「信号日当天」收益
...
prev_ret[t, j]                        # ← 我当它当「前一日」用
```

后果：因为 `close[t]/close[t-1] = (1+gap[t])·(1+intra[t])`，而信号样本 gap 几乎固定在 −6.7% 附近，**按 prev_ret[t] 分组 ≈ 按 intra[t] 分组 = 循环论证**。于是得出「前日跌停组 46 只、均值 −3.22%、胜率 0.0%」这个荒谬结果。

**是靠抽 5 例原始 bar 翻出来才发现的**（项目纪律第⑭条又一次应验）。正确口径 `prev_ret[t] = C[t-1]/C[t-2]-1` 下重算，V1 结果为：

| 前一日状态 | n | 均值 | 胜率 |
|---|---|---|---|
| 前日跌停（≤ −9.5%） | 36 | +4.22% | 72.2% |
| 前日大跌（−9.5%~−5%） | 27 | +3.22% | 59.3% |
| 前日小跌（−5%~0） | 45 | +3.64% | 73.3% |
| 前日上涨（>0） | 78 | +3.54% | 64.1% |

**各组差异不大 → 信号与「前日是否跌停」无关**，这是好消息（说明不是纯撬板效应），也说明第一版结论必须整批作废。

### 4.3 五条不能越过的边界

| # | 边界 | 依据 |
|---|---|---|
| **B1** | **2026H2 已显著衰减**：均值 +2.22%、胜率 48.9%（vs 2025H2 的 79.7%） | `audit_round114f.V5` |
| **B2** | **无分钟线 → 开盘成交率未验证**。低开 6%+ 的股票，开盘买盘排队极长 | 硬约束 |
| **B3** | **盘中最大回撤未知**。只知 open→close，不知中途是否先跌 5% | 硬约束 |
| **B4** | **事件风险**：低开 6%+ 常伴随立案/退市/业绩爆雷，需人工排除 | 无法量化 |
| **B5** | **样本仅 341 日单期**，跨不了牛熊 | 硬约束 |

**因此定位只能是**：观察名单触发的**人工决策辅助**（"今天这只低开 7%，别急着砍"），**不是自动化信号，不承诺胜率，不给仓位比例**。

## 5. Transformer 结论（对第 1 条需求的收尾）

| 指数 | 样本外准确率 | 基线 | 差 | p（单侧） | 判定 |
|---|---|---|---|---|---|
| 中证全指 | 49.57% | 52.94% | −3.37pp | 0.989 | 不如基线 |
| 沪深300 | 54.23% | 54.66% | −0.43pp | 0.615 | 不如基线 |
| 中证500 | 48.36% | 53.63% | −5.27pp | 1.000 | 不如基线 |
| 中证1000 | 51.47% | 50.60% | **+0.87pp** | **0.277** | 名义跑赢但不显著 |

Bonferroni α = 0.05/4 = 0.0125 → 4 次检验至少一次假阳性概率 ≈ **18.5%**。

**已排除「实现有 bug」**：numpy 手写版（梯度检查 16 个张量全部 rel_err < 1.2e-07）+ 官方 PyTorch 版（手写 AdamW 绕开 torch 2.15 dynamo 崩溃）两套独立实现，结论一致——都不如基线。

**页面已明写「不提供仓位建议」**，这是数据纪律要求，不是能力退缩。
