## 一、P0-1｜fund 维评估域诊断（结论被本轮二次修正）

### 1.1 根因不是「数据缺失」，也不是「域错配」，而是「影响力度偏差」

本轮把诊断固化为独立工具 `domain_mismatch_diag.py`，跑出的结果**推翻了 round99 自己上一轮的结论**：

**round98 的判断**：`panel_round66.json` 里 fund 覆盖率中位 0.0000，仅 80/238 截面有值 → 「数据缺失」。

**round99 的判断**：fwd_hist 内部覆盖 100%，是「评估域错配」（2029 全池稀释了覆盖率）。

**round101（本轮落地）的实测**：

```
score_fund  快照截面 89 个  (data/fwd_hist)
  可比截面 63  (2026-06-26 ~ 2026-09-22)
  同域规模中位 191 只  面板覆盖率中位 0.0907  Jaccard 重叠 0.9731  稀释 10.6x

  口径                   n      IC均值     ICIR       t    显著
  同域(快照)              63    0.0897   0.6494    2.74     Y
  面板(该维有值)            63    0.0941   0.6726    2.86     Y
```

**关键点：Jaccard 重叠 0.9731。** 说明「同域」和「面板该维有值」几乎是同一个集合——round99 声称的「同域 vs 全池对照」**根本没有对照上**，两个 IC 必然几乎相同（0.0897 vs 0.0941）。那个「域错配」诊断是不成立的。

那么真正的问题是什么？**覆盖率只有 9.07%**。

这引出一个比「数据缺失」更严重的机制：`composite()` 的实现是**缺维从分母剔除后重归一**（禁 `or 0`，这是正确的）。后果是：

> fund 名义权重 0.200，但只对 9.07% 的股票生效。对其余 90.93% 的股票，fund 从分母消失，剩余维度按比例放大。
> ⇒ 对**被 fund 评分的那 9% 股票**，fund 的实际暴露约 **11.0x 名义值**；对其余 91% 的股票，fund 暴露为 0。

这是记忆中「P0-4 混合量尺」问题在 fund 上的具体表现：**同一个 total 分数，不同股票的权重结构完全不同，绝对分不可比。**

**本轮结论**：
1. fund 单维 IC = +0.0897（t=2.74）**显著为正，确实有 alpha** → round97 判 fund=0 是伪结论，已彻底推翻
2. 但「有 alpha」≠「可这样用」：11x 的暴露放大意味着 fund 在打分里**实际扮演的角色远超其名义权重**
3. 评估域必须用重建池（`data/pit_pool.json`），且**必须同时报覆盖率**，否则读者无法判断暴露偏差

**落地物**：`domain_mismatch_diag.py` + `domain_mismatch_diag.json`
- 自动算覆盖率、Jaccard 重叠、稀释倍数、暴露偏差
- 四类裁决：两口径均显著 / 域错配 / 均不显著 / 反向错配
- 有 `exposure_bias` 字段直接给出「实际暴露 = N x 名义值」

### 1.5 🛑 附带发现的 P0 级事故隐患（本轮最具实操价值）

在准备「更新今日数据」时核查链路，发现一个此前从未被注意的**静默降级路径**：

```
run_daily_local.sh  Step 3.96
  → factor_eval.py --optimize-weights
    → optimize_weights()  产出 result["version"] = "v3.6-fund-led"（硬编码）
      → json.dump(result, open(WEIGHTS_PATH, "w"))   ← 整份覆盖
```

**后果**：一次日常跑批就会把线上 `v4.15-constraint-cap`（含 `weight_constraints` 元信息 + 九维约束化权重）**整份替换成 v3.6**。连带影响：
- `verify_weights_round36.py` 的约束校验会退化为「默认口径」**且不报错**（因为 `weight_constraints` 字段消失了，代码走了 `else` 分支）
- 页面权重条同步变化，但**没有任何告警**
- 记忆铁律「改动只在本地、未修改线上权重」会被一次例行跑批从内部破坏

**为什么一直没爆**：`optimize_weights()` 开头有「十维守卫」——若前 5 个快照无 `score_oversold60` 等新维字段则 `return None, None` 直接跳过。近期快照都带十维，守卫已不再生效。

**修复**：加**权重覆盖守卫**——
- 检测现存权重是否「受约束管理」（`weight_constraints` 存在 或 `version` 以 `v4.` 开头）
- 是 且 未显式加 `--force-overwrite-weights` → **拒绝覆盖主文件**，改写 `factor_weights_optimized_YYYYMMDD.json`，并在输出 json 写 `weight_optimization_skipped_overwrite` + 打印 🛑 告警
- 否则沿用原行为

**验证**：`cur_ver=v4.15-constraint-cap / cur_managed=True / force=False → 会覆盖主文件？False`；`py_compile` 通过；跑完链路后 `factor_weights.json` 与备份逐字节一致。

**这条教训要进工程纪律**：任何「优化器输出写回单一配置单一入口」的设计必须带版本守卫。`version` 字段在结果组装里硬编码 = 覆盖即降级，属于记忆中「静默 P0」的变体。

## 二、P0-2 / P0-3 / P1-2｜验收门禁硬化（本轮最重要交付）

### 2.1 从「审计脚本里的临时逻辑」升级为独立裁决器

新文件 `weight_admission_gate.py`，任何权重候选（优化器输出、人工指定、线上文件）都必须过它才能上线。

五道门禁：

| 门禁 | 判据 | 对应问题 |
|---|---|---|
| **G1** monotonic_robust | 相邻档差无**统计显著**的下降，且 Q5>Q1 | P0-3 分层单调性 |
| **G2** spread_positive | Q5−Q1 > 0 | P0-3 互补 |
| **G3** beat_ew | 组合 ICIR > 同因子池等权 ICIR | 优化必须优于零参数 |
| **G4** beat_single | 组合 ICIR > 最强单因子 ICIR | 合成必须优于单打 |
| **G5** wf_pass_rate | walk-forward 折通过率 ≥ 50% | P1-2 过拟合门禁 |

### 2.2 G1 判据被迫改造——这是本轮的一个方法论发现

初版把「严格单调 Q1<Q2<Q3<Q4<Q5」当一票否决。实跑后被**三个方案全部否决**，于是做了显著性标定：

```
方案                      档        均值       SE      差(相邻)      差SE      t
v4.15                Q1     0.03701  0.01111          -        -      -
                     Q2     0.03361  0.00996   -0.00340  0.01492  -0.23
                     Q3     0.03840  0.01011   +0.00479  0.01419  +0.34
                     Q4     0.03320  0.00850   -0.00520  0.01321  -0.39
                     Q5     0.02192  0.00611   -0.01128  0.01047  -1.08

cand_p11_flip005     Q1     0.03255  0.00906          -        -      -
                     Q2     0.01692  0.00867   -0.01564  0.01254  -1.25
                     Q3     0.03299  0.00937   +0.01607  0.01277  +1.26
                     Q4     0.03332  0.00887   +0.00033  0.01291  +0.03
                     Q5     0.04812  0.00912   +0.01481  0.01273  +1.16

等权3稳定维              Q1     0.03015  0.00864          -        -      -
                     Q2     0.01859  0.00855   -0.01157  0.01216  -0.95
                     Q3     0.03451  0.00896   +0.01592  0.01239  +1.29
                     Q4     0.03146  0.00924   -0.00304  0.01287  -0.24
                     Q5     0.04916  0.00961   +0.01770  0.01333  +1.33
```

**3 个方案 × 4 个相邻差值 = 12 个统计量，|t| 最大 1.33，无一显著。**

标准误约 0.010~0.015，而档间真实差异只有 0.003~0.018。**严格单调在这个样本量下等同于「要求噪声按指定顺序排列」。**

因此 G1 改为**噪声容忍判据**：只把 `diff < 0 且 |t| ≥ 1.5` 的下降当真实断裂；严格单调保留为**诊断字段**（`monotonic_strict`），不作门禁。

这是必要的设计而非放宽标准——否则门禁会否决一切方案，失去区分度。改造后立即可区分：

| 方案 | G1 | G2 | G3 | G4 | G5 | 裁决 |
|---|---|---|---|---|---|---|
| **v4.15（线上）** | N | **N** | N | N | N | **FAIL（G1/G2 即否决）** |
| cand_p11_flip005 | Y | Y | Y | Y | **N** | **FAIL（仅卡 G5）** |

### 2.3 过拟合门禁把一个隐藏风险显式化了

初版 walk-forward 用 `--pool` 默认 4 维（剔除 fund，因其不可回溯），网格 35 组 × 20 验证点 → **选择自由度 2:1**。

对比 round97：16807 组 × 19 验证点 = **885:1**。

门禁现在会主动打印 `selection_dof_ratio`，超过 10:1 就标 `overfit_warning`。这一条把「枚举了多少组 / 只有多少验证点」这个此前被埋在脚本里的数字，变成了裁决输出的一部分。

## 三、P1-1｜翻转维度权重取舍（代价曲线是本轮最有决策价值的产出）

round94 实测 4 维在涨/跌市符号翻转（ep / lowvol20 / rsi_rev / tech_neg），v4.15 里合计权重 **0.4244**。本轮做压缩扫描：

| 翻转维权重 | 全样本ICIR | 涨市ICIR | 跌市ICIR | spread | 严格单调 |
|---|---|---|---|---|---|
| **0.4244（现状）** | 0.3246 | **−0.2912** | 0.8335 | 0.00580 | N |
| 0.3500 | 0.3623 | −0.2111 | 0.8520 | 0.00792 | N |
| 0.3000 | 0.3980 | −0.1369 | 0.8701 | 0.00972 | N |
| 0.2500 | 0.4464 | −0.0389 | 0.8952 | 0.01090 | Y |
| 0.2000 | 0.5164 | +0.0958 | 0.9320 | 0.01145 | N |
| 0.1500 | 0.6243 | +0.2924 | 0.9809 | 0.01309 | Y |
| 0.1000 | 0.7956 | +0.5860 | 1.0340 | 0.01311 | Y |
| **0.0500** | **1.0206** | **+1.0386** | 0.9993 | 0.01319 | N |
| 0.0000 | 0.9623 | +1.6356 | 0.5621 | 0.01451 | N |

**三条读法**：

1. **代价几乎为零，收益却很大。** 压到 0.05 时全样本 ICIR 从 0.3246 升到 **1.0206（3.1 倍）**，而跌市 ICIR 只从 0.8335 微升到 0.9993（没损失）、涨市从 −0.2912 转为 **+1.0386**（从拖累变贡献）。
2. **存在明确的最优区间，不是越压越好。** 压到 0 时全样本 ICIR 反而降到 0.9623（低于 0.05 的 1.0206），因为跌市 ICIR 从 0.9993 崩到 0.5621——**翻转维提供了真实的跌市捕获力**。这解释了为什么不能简单归零。
3. **spread 随压缩单调上升**（0.0058→0.0145），说明翻转维的主要副作用是**压平分层**（惩罚过度导致 Q5 被打低），这与 §2.2 的「Q5 系统性偏低」判断一致。

**候选权重（未上线）**：

```
score_fund 0.453978 / score_size_growth 0.259416 / score_quality 0.226989
score_lowvol20 0.028095 / score_ep 0.016857 / score_rsi_rev 0.010620 / score_tech_neg 0.004046
```

重建池域表现：**IC=0.0600, ICIR=0.9822, t=7.52**（v4.15 为 IC=0.0383, ICIR=0.2445, t=1.71）→ **ICIR 提升 +301.7%**。

**但这个候选用不了，两个硬障碍**：
- **违反 v4.15 约束**：fund .454 / size_growth .259 / quality .227 三项均超「单因子 ≤0.20」上限，基本面大类 0.68 超「大类 ≤0.30」上限。记忆中 round89 已证「放宽约束边际收益极小」，但**违反约束本身是个治理问题**，不能因为收益大就破例。
- **卡在 G5**：walk-forward 6 折只过 1 折（16.7% < 50% 阈值）。

⇒ **正确处置是「记录为最强候选、等约束重解」而非直接上线**。

## 六、必须一起说出口的边界（禁止单独引用任何数字）

1. **v4.15 现在仍在线上跑，而它五道门禁 0 通过。** 这不是「新发现的风险」，而是**此前一直在承担但没被量化的风险**。本轮的价值是把它变成可见的裁决结果，不是制造问题。
2. **不要因为候选 ICIR 提升 301.7% 就认为模型变好了。** 那个候选：违反三条权重约束、walk-forward 只过 1/6 折、6 折里 5 折 spread 不显著。提升来自「压缩了会拖累的维度」，不是「发现了新 alpha」。
3. **严格单调在本样本量下统计上不可达**（12 个相邻差值 |t|≤1.33）。任何声称「已实现分层单调」的表述都需要先给出档间差值的 t 值。
4. **G1 用噪声容忍判据是本轮的自主判断**，不是老大指定。若认为应坚持严格单调一票否决，则当前**没有任何方案（含线上）能通过**——这个取舍需要老大明确。
5. **每一项结论都只在 219 个截面 / 2025-11-03~2026-09-22 上成立。** 记忆中已多次证明换样本后结论可能整批作废。
