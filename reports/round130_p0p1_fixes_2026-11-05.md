## 1. P0-1 冻结模型 + 统一生产/历史评分内核

### 根因（三层）
1. **量尺分叉**：`recompute_ic_long_v2.py:143-157` 用 `comp = (S @ W/DMAX) / (mask @ W/DMAX)`，
   分母**随每只股票缺几维而变**；生产 `scale_calc.composite_total` 用**固定名义权重分母 + 缺维中性填充**。两把尺子不是同一模型。
2. **因子代际分叉**：`build_panel_long.py:373-455` 的历史 `size_growth`=流通市值分位、
   `quality`=ROE 分位、`growth`=归母净利同比分位、`fund`=None，未复现生产算法与 v4.19 三门槛。
3. **证据误用**：`data/ic_long_2020.json` 仍标 v4.18，却被页面当作当前生产模型的权威证据。

### 修复
| 文件 | 改动 |
|---|---|
| `scoring_core.py`（新） | ① `composite_total_matrix()`：与 `scale_calc.composite_total` **逐股等价**的向量化内核（固定分母、缺维中性填充、整列缺失自动补盲区）；② `kernel_fingerprint()`：权重版本/dim_max/中性比例/8 个核心源码 SHA-256 → `kernel_id`；③ `classify_artifact()`：UNKNOWN / LEGACY / PROXY_ONLY / COMPARABLE 四态守卫；④ `selfcheck()` 真实数据逐股比对 |
| `recompute_ic_long_v2.py` | 合成分默认切 `production` 统一内核；`IC_KERNEL_MODE=legacy` 仅供对照；`--selfcheck` 只验内核不写产物；产物写 `kernel` / `results_kernel` / `evidence_boundary` + 迁移说明 |
| `build_panel_long.py` | 面板元数据写 `kernel` / `factor_parity=False` / `factor_proxies` / `pit.provenance` / `evidence_boundary` |
| `factor_eval.py` | 把长面板的 `kernel` 三键**透传**到页面唯一入口 `factor_ic.json → long_panel_ic` |
| `gen_report_top200.py` | 渲染时真实调用 `classify_artifact()`，紧跟长面板数字追加守卫披露行 |

### 影响范围
- **合成层：完整闭环**。同一输入、同一时点逐股总分一致已由真实面板 256 股验证。
- **因子层：如实标注为不可闭环**（见 §5 边界）。守卫使任何旧口径/代理面板产物**自动判为不可互证**，页面已生效（`UNKNOWN`）。
- 本次**刻意不重跑**长面板 IC：重跑会改变 IC/DSR/页面数字，需同步 `factor_eval → ic_dsr → 页面` 整条链；
  为避免证据链断裂，改为「代码内核已统一 + 现有产物标旧代际 + 给出一次性迁移命令」。
  迁移命令：`python recompute_ic_long_v2.py && python factor_eval.py && python ic_dsr.py && python gen_report_top200.py <scored> <out>`。

## 2. P0-2 风险预算、行情覆盖、最终权重硬约束

### 根因
- `pick_portfolio.load_w_total()` 六条分支（缺文件 / 解析失败 / 门禁失败 / 字段缺失 / 非数值 / 越界）
  **一律回退满仓 1.0** → 故障反而扩大风险；且 `final_hi=0` 被判为非法。
- `portfolio_risk.py` 逐日循环算出的 `wsum` **从未被使用** → 缺价持仓被静默当作 0 收益，
  无人知道当天覆盖了多少权重，波动/回撤被系统性低估。
- 行业只数限制 ≠ 最终权重限制；选不满时未对最终权重重新验收。

### 修复
| 文件 | 改动 |
|---|---|
| `pick_portfolio.py` | ① `load_w_total()` 重写：故障默认回退**空仓 0.0**（`--risk-fallback zero/conservative/full`，仅 `full` 回满仓且标不可执行）；合法 `final_hi=0` 保留且 `executable=True`；`combine.available=False` 新增门禁；`info` 必带 `executable` / `budget_status`。② 新增 `validate_final_weights()`：Σ权重+现金=1、非负、不得突破 `w_total`、单票上限按 scope。③ 新增 `--auto-cap-scale`（**默认关闭**）：选不满时按单票上限反推缩减仓位、缺口留现金。④ 产物顶层与每条路线写 `executable` / `final_weight_validation` / `cap_scaled` |
| `portfolio_risk.py` | 新增 `MIN_PRICE_COVERAGE=0.80`；用 `wsum` 逐日算**有效持仓权重覆盖率**（分母为持仓市值、不含现金）；输出 `price_coverage_mean/min`、`n_days_below_coverage`、`coverage_gate_ok`、`missing_price_policy`；门禁不通过时把 vol/mdd/beta/收益全部置 None 并提前返回 |
| `test_round122_portfolio.py` | 旧断言（故障回满仓 1.0）按新契约更新并**加强**：新增 `executable`、`budget_status`、0 仓位合法性、显式 full 回退仍不可执行；`0.0` 从"非法值"构造数据移出，单独立用例 |

### 真实运行证据（写向 /tmp，未覆盖生产产物）

- 故障三档：`zero→0.0` / `conservative→0.2` / `full→1.0`，**全部 `executable=False`**；合法 0 预算 `w=0.0, fallback=False, executable=True`。
