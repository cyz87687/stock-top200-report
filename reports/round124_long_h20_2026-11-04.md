## 二、本轮发现并修复的 3 个致命 bug

### BUG-1 `score_ep` 与 `score_size_growth` 是同一列（最严重）

```
旧实现: s_ep = rank10({c: 1.0/cmv[c]}, higher_better=True)
        s_sizeg = rank10(cmv, higher_better=False)
        → 秩上数学等价

实测:   ρ = 0.99999999
        分维度 IC 完全相同（都 +0.0337 / NW t 2.27 / 胜率 0.599 / n=1635）
        → 名义 0.20 + 0.10 = 0.30 权重被重复计数
```

**修复**：EP = 归母净利润（PIT 最新一期）/ 流通市值，仅对盈利为正排序（亏损股 EP 无经济意义，显式剔除而不给低分）。

**效果**：
```
ρ          0.99999999 → 0.1015
EP 独立 IC  —          → +0.0278 (t 2.74)
h=20 NW t   4.25       → 5.87
h=20 IC     0.0474     → 0.0539
2020 年 IC  +0.001     → +0.041（不再接近 0，单调性问题基本消失）
```

### BUG-2 幸存者偏差：2020 年后退市的 247 只全部缺失

```
现象: domain_2029 取自「当前在市候选池」
实测: 原库 2029 只里 99.5% 活到 2026-11-03，中途消失仅 11 只 —— 这不可能
连带: data/fin_cache_em 对 247 只退市股覆盖 = 0/247
修复: fetch_delisted_since2020.py 拉齐（行情 239 ok / 4 empty；财务 243 ok）
结果: klines_2020.npz 2029 → 2257 只；消失股票 11 → 238 只
      IC +0.0494 → +0.0474（方向正确：只留活着的股票会略微高估）
```

### BUG-3 退市股接口 12 列导致字段整体错位

```
在市股 11 列: ['日期','开盘','收盘','最高','最低',...]
退市股 12 列: ['日期','股票代码','开盘','收盘','最高','最低',...]  ← 多一列
→ 位置索引 r[1..7] 整体错位一列 → open 被写成「股票代码」
实测 000038: open 恒等于 38.000（恰是代码后 5 位）、low(12.27) > high(12.11)
后果: high<low 167,871 条 / close 越界 182,469 条
修复: 改用列名 r["开盘"]/r["收盘"]/...  → 三项异常全部归零
```

同批修复：退市股财务缓存格式（第一版写成 `{类别:{报告期:值}}`，与主缓存 `{sym,cached_at,records:[...]}` 完全不同 → `load_fin()` 只认 `records` → 退市股 ep/quality/growth 会**静默全 None**）。

- ❌ 不得说「经验证的 alpha」；本轮结论全部来自**同一段构造期**，`n_eff=81.8` 只是让 t 值可算
- ❌ 不得把 `score_growth` 的 0.10/0.20 说成「IC 背书」；它的 IC 只有 +0.0132 (t 1.37)
- ✅ 可以说「在当前 regime 内有效」，并同时给出 2022 年 IC 仅 +0.020 的事实
