## 1. 评估：五个必须知道的实测事实

### 1.1 ⭐⭐⭐ IC 的截面规模与生产池差 10 倍（本轮最重要的发现）

`factor_ic.json` 里 `current_weights_composite_ic` 声称 `n_snapshots=80`，但没披露**每个截面有多少只股票**。实读 `factor_history.json` 逐截面统计：

| 项              | 实测值                        |
| -------------- | -------------------------- |
| IC 使用的截面数（h=1） | 79                         |
| 每截面股票数 **中位**  | **194 只**                  |
| 股票数 <300 的截面   | **69 / 79（87%）**           |
| 股票数 ≥1000 的截面  | **1 个**（2026-10-26，1895 只） |
| 最近 10 个截面      | 490×9 + 1895×1             |
| 当前生产池          | **2,084 只**                |

|                                          |                                                                                                |
| ---------------------------------------- | ---------------------------------------------------------------------------------------------- |
| **后果**：`tradable_w_ic` 的 \`verdict="显著有效 | IC=+0.117，NW t=2.21（宽松显著·未过多重校正）（T+5）"\`，这个结论**主要来自老的小池 + 老因子集时期**，与现在的 2,084 只池 × 20 维不是同一个域。 |

我复算了加门槛后的样本留存：

| 门槛（每截面最少股票数） | h=1 剩余截面 | h=5 剩余截面 | h=20 剩余截面 |
| ------------ | -------- | -------- | --------- |
| 无门槛（现状）      | 79       | 76       | 61        |
| ≥200         | 10       | **7**    | **0**     |
| ≥500         | 1        | 0        | 0         |

h=20 在 ≥200 门槛下**直接归零**。也就是说"当前权重在 h20 上有 +0.1118 的 IC"这句话，在"截面至少 200 只"这个最低要求下**无法复现**。

**这不是补数据能解决的**，是已有数据的口径标注问题。修法见 P0-1。

### 1.2 ⭐⭐ K 线库的 341 个日期里，只有 305 个是真实横截面

`klines_long.json` 并集日期 341 个（2025-06-09 ~ 2026-11-02），但按日统计有 bar 的股票数：

| 覆盖只数        | 天数        | 日期区间                        |
| ----------- | --------- | --------------------------- |
| 1 ~ 10 只    | **23 天**  | 2025-06-09 ~ 2025-07-09     |
| 10 ~ 100 只  | 9 天       | 2025-07-10 ~ 2025-07-22     |
| 100 ~ 500 只 | 4 天       | 2025-07-23 ~ 2025-07-28     |
| **≥2000 只** | **305 天** | **2025-07-29 ~ 2026-11-02** |

股票起始日分布：**1,913 只股票的第一根 bar 都是 2025-07-29**。前 36 天是少数几只老股的残留 bar。

**后果**：任何按「341 个日期」做分母的统计（覆盖率 88.1%、样本量、窗口长度）都被稀释了。真实可用是 **305 日**。项目记忆里"341 日"的表述需要改为"305 个有效横截面（并集 341 日）"。

好在 `recommendation_track.json` 的 `_meta.calendar` 已经是正确的：`{"n_days":304, "start":"2025-07-29", "end":"2026-10-30"}` —— 说明这条链自己是对的，只是别处的口径没同步。

### 1.3 ✅ 前复权锚点目前是干净的（好消息，但不可依赖）

此前担心"增量追加 `append_klines_latest.py` 只追加不覆盖 → 除权后历史价与新增价锚点不一致"。实测 30 只（库内有完整 305 天的）：

```
库内 close / 东财 qfq close 比值中位：
  30 只全部 = 1.000000（最大偏离 0.0009）
  最早 10 日比值 与 最晚 10 日比值 一致 → 无锚点漂移
```

**结论：当前库没有锚点混用问题。** 但要清楚这只是"这段时间刚好没除权"，不是机制保证。`append_klines_latest.py` L129 的注释写着「已有日期绝不覆盖」，一旦某只股票除权，历史 bar 会与新 bar 处于不同锚点，且**脚本不会报错**。所以 P0-1 之外仍需一条锚点自检（见 P1-1）。

### 🔴 P0-1　给 IC 加 `min_cross_section` 门槛并披露截面规模

**问题**：79 个 IC 截面里 69 个只有 ~194 只股票，生产池 2,084 只。h=20 在 ≥200 门槛下**样本归零**。

**为什么是 P0 而不是 P1**：这是**已经对外输出的数字**。页面写着"综合分 IC=+0.117，NW t=2.21 显著有效"，但没说这是 194 只股票上的结果。作为量化从业者，这是最不能接受的披露缺失 —— 比"样本短"严重得多，因为**短的样本至少是诚实的**。

**具体动作**：

1. `factor_eval.py` 计算 IC 时，按截面股票数过滤，新增参数 `min_cross_section`（建议默认 **200**），并在 `factor_ic.json` 每个 horizon 下写出：
   ```json
   {"n": 79, "n_after_gate": 10, "median_cross_section": 194,
    "min_cross_section_gate": 200, "dropped_by_gate": 69}
   ```
2. `gen_report_top200.py` 的 IC 章节**必须**同时显示：截面数 / 每截面股票数中位 / 门槛 / 幸存截面数。
3. 对 h=20 明确写出「在 ≥200 只门槛下无有效截面，故 h20 IC 不可引用」。
4. 检查 `factor_history.json` 为什么只有 ~194 只 —— 是 `factor_eval` 的写入域限制，还是历史遗留小池？**必须查清**，因为这决定了门槛加了之后还剩多少。

**验收标准**：`factor_ic.json` 里每个 horizon 都能看到 `median_cross_section` 与 `n_after_gate`；页面 IC 段落出现"每截面 N 只（中位）"。**在此之前，P0-2 之后的任何权重讨论都不应引用 IC 数字。**

**预估工作量**：0.5 天（改 1 处计算 + 1 处渲染 + 1 处诊断）

## 5. 明确撤销的议题（不要再提）

| 议题 | 撤销理由 |
|---|---|
| **分钟线 / T0 回转** | 用户本轮已限定「个股数据只需要日级别维度」。T0 必然需要分钟线，**议题随之整体撤销**。此前 round113/114 的 T0 成本上限研究保留为历史结论，不再推进。 |
