老大提供的业绩数据 完全准确（Wind + 东财双源交叉验证一致）。
真正的问题是：score_quality 这一维整体不可用 —— 它不是「算错了一点」，而是同一份数据每次算出的结果都不一样。
威海广泰的质量分 8.74 不是任何一次真实计算的产物，它只是某一次随机行序的偶然结果。 同一数据、同一日期，仅打乱输入顺序重算 9 次，得到：

二、根因链：一个 nan 打穿整个排序
fund_split.py —— 五个环节都有「NaN 能通过」的漏洞，缺一不可
① 入口：东财缓存里「商誉」对无商誉公司返回 nan（不是 None）， _fnum() 把它当 float 接受 → 存入缓存。但 这是数据源特性，不是错。
② 子因子：if gwv is not None → nan 不是 None，放行 → 算出 gw = nan。
③ 族分：fam() 用 isinstance(v, (int,float)) 过滤 —— nan 是 float，能过 → 组均值被污染 → qf = nan。
④ 入池：present = [i for i,v in enumerate(raw) if isinstance(v,(int,float))] —— 同样的判定，nan 进入分位池。
⑤ 致命一击：rank_pct() 用 sorted(range(n), key=lambda i: vals[i]) 排序。 而 Python 里 nan 的任何比较都返回 False —— 排序算法的分治逻辑随之崩坏， nan 被散布到数组各处，所有真实值的秩被彻底打乱。
📌 为什么这个问题特别毒：它不报错、不崩溃、退出码 0。 排序「成功」了，只是顺序是错的。而且 score_rows 的输入顺序由上游决定（按 total 降序）， 所以每次跑数都不同、每天不同、换台机器也不同 —— 产生了「看起来像 alpha」的假信号。

四、比算错更严重：quality 的「alpha」是总分泄漏的伪影
排序塌陷后，虽然秩乱了，但仍部分保留了输入顺序 —— 而输入顺序 = 当期总分降序。 于是 score_quality 里被注入了「总分」的信息。实测：
rank corr（污染版 quality ↔ 上期 total）= +0.3910，t = +65.05
上期 total 自身 IC：h5 +0.1524 / h20 +0.2102 / h40 +0.3414
所以 round34 里算出的「quality h20 IC = +0.0361，t=5.10，过 Bonferroni」—— 不是质量的 alpha，是总分泄漏过来的。 把上期 total 的影响剔掉之后，残差 IC 立刻翻负：
残差 IC：h5 −0.0746(t −3.18) · h20 −0.0796(t −4.42) · h40 −0.1223(t −5.70)
结论：round34 关于 quality 通过 Bonferroni 的那条裁决作废。

📌 这里必须说清楚：负 IC 不是 bug，是市场事实。 纯 ROE 因子 h20 IC 达 −0.147（t = −14.72），这种量级的负值不可能是程序缺陷 —— 它反映的是当前 3 个月窗口小盘投机风格主导，高 ROE / 高质量被系统性抛售。 模型的问题不在于「质量因子失效」，而在于给一个当时逆风的因子 12% 权重，还以为它有 +0.036 的 alpha。
六、其余四处独立缺陷（都不依赖 NaN）
缺陷 A · ROE 死区：3%~8% 完全没有分支
elif _roe >= 0.08: 一般 与 elif _roe < 0.03: 扣分 之间是一片空白 —— ROE 在 3%~8% 之间既不加分也不扣分。威海广泰 4.25% 正落此区。
全池落在该区间的有 526 只（27.8%），其中 136 只 score_fund ≥ 4.0。
缺陷 B · 用累计同比代表当期景气
模型吃的 growth = 28.57% 是前三季度累计同比， 完全掩盖了单季 −92.90%。
q3_yoy / q3_accel / q3_implied_h2 全为 null → Q3 景气加分机制从未触发。 单季崩塌这个最重要的坏消息，根本没进模型。
缺陷 C · PIT 时点不一致
quality 用中报 20260630（三季报法定披露截止 10-31 > 截面日 10-26，被 PIT 正确排除）， 而 growth 用三季报 20260930。同一只股票，两条链路看的是不同报告期。
PIT 本身设计是对的，但两个维度口径不齐，会让「质量看半年报、成长看三季报」这种拼接结果无法解释。
缺陷 D · 组内量纲混杂，负债率压倒一切
「稳健与风控」组内：debt = −49.69（负债率百分比）、profit_vol = −1.95（标准差）、 gw = −0.32。直接算术平均 → 负债率一项独力把整组拉到 −13.93。
三组合计：资本回报 4.11 · 现金流质量 1.04 · 稳健风控 −13.93 → qf = −2.93。 ROE 再高也拉不回来，因为分子分母根本不同量纲。
七、8 维 vs 4 维：结论不变，但理由必须换掉
结论：维持 8 维，不采用 4 维等权。
但原来支撑这个结论的理由（「4 维 h20 IC 低 0.0289」）已经不能用了， 因为那个对比里 quality 是污染值。

换成这个理由：4 维方案（低波 25% + 行业内市值 25% + 质量 25% + fund 25%） 把 quality 权重从 12% 提到 25%。而 quality 修复后的残差 IC 是 h20 −0.0796（t = −4.42） —— 把四分之一的仓位押在一个统计显著的负向因子上，是自毁。

同时要说的是：8 维里的 quality 本身也该动。 现在给它 12%，相当于每天主动做一个 t=−4.42 的逆向下注。是降权、归零、还是反向使用， 这是独立的一次裁决，我不擅自改。

所以我没有动任何一行 fund_split.py。 代码已定位、证据已固化、备份已就位，等老大点头再改。
九、建议的修复方案（四处，均为最小改动）
① 入口统一：_fnum() 与 sub_factors_pit() 加 math.isnan/isinf 防御。项目里 scale_calc.is_num 已有 x == x 的正确写法， 复用同一实现，不要再各写一份。
② 族分过滤：fam() 的 isinstance(v,(int,float)) 换成 scale_calc.is_num(v)； score_rows.present 同样处理。
③ 分位兜底：rank_pct() 开头直接剔除 NaN， 并在函数内断言 all(v == v for v in vals) —— 宁可抛异常，也不要静默算错。
④ 确定性回归测试：加一条自检 —— 同一批数据打乱行序重算 3 次， 结果必须完全一致，否则 pipeline 直接失败。这次问题的本质是「不确定」，必须用测试锁死。
