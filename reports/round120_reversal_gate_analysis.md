## 1. 代码事实：判定条件只有单一阈值，无任何前置约束

`step2_stockscorer_v2.py` 里三个反转打分函数，**输入只有单一标量，结构上就无法加形态约束**：

```python
# L2734
def score_rsi_rev(rsi14):          # 只吃 RSI，连价格都不传
    if rsi14 is None: return 2.5
    if rsi14 < 30: return 5.0      # ← 唯一的判定条件
    if rsi14 < 40: return 4.0
    if rsi14 < 50: return 3.0
    if rsi14 < 60: return 2.0
    return 1.0

# L2721
def score_bias60(price, ma60):     # 只看偏离深度
    bias = (price - ma60) / ma60 * 100.0
    if bias <= -15: return 5.0
    ...

# L2709
def score_oversold60(mom60):       # 只看跌幅
    if mom60 <= -30: return 5.0
    ...
```

调用点（L5177-5179）：

```python
s_oversold60 = score_oversold60(_mom60_v)
s_bias60     = score_bias60(price, _ma60_v)   # 只传 price 和 ma60
s_rsi_rev    = score_rsi_rev(_rsi14_v)        # 只传 RSI
```

**关键结构问题**：`score_rsi_rev` 的签名里没有 `price`、没有 K 线、没有量能。**想加任何形态/企稳约束，必须改函数签名 + 改调用点**，不是加个 if 就行。

### 权重实况（纠正一个常见误记）

| 维度 | 权重 | 状态 |
|---|---|---|
| `score_bias60` | **0.05** | 生效 |
| `score_rsi_rev` | **0.05** | 生效 |
| `score_oversold60` | **0.00** | **v4.4 已归零，不进总分** |

→ 生效的反转权重合计 **10%**（不是 15%）。`dim_max` 均为 5.0，页面折算到 10 分制。

### 页面那个「10 分」怎么来的

`gen_report_top200.py:592` 定义了反转块的显示口径：

```python
_TECH_BLOCK_KEYS = ("score_bias60", "score_rsi_rev")
```

两维都满 5.0 → 归一化到 10 分制后加权平均 → `(10×0.05 + 10×0.05) / 0.10 = 10.00`。

**所以「乖离/RSI反转强(9.00/10)」是两维双满分的合并显示**，不是某一维得了 9 分。

## 4. 实证裁决：加前置条件到底有没有用

### 4.1 为什么这一节的口径必须重做

前四轮审计（120b/120c/120d/120e）各用了不同口径，产生三处互相矛盾的数字，**已全部作废并在此说明**：

| 矛盾 | 成因 | 处置 |
|---|---|---|
| 120b T1 报 −0.615、T2 报 +0.615 | true/false 角色互换，字段同名 | 本报告统一定义为「差 = A − B」 |
| 120d/120e 分档中位 0.069 / 0.120 | 两组用各自出现日，创新低 132 天 vs 不创新低 108 天，**不是同一批日期** | 改为严格按日配对 |
| 120e `excess_mean` 15 档全为正 | 超额基准是「当日全池**中位数**」，而全池均值−中位差 = 1.123pp，机械抬正 | **`excess_mean` 一律作废** |

### 4.2 口径对账（这是本轮最重要的技术发现）

同一个「RSI<30 内 不创新低 − 创新低」，四个开关组合：

| step | 新低口径 | 单日最小样本 | 配对天 | 差值 | t |
|---|---|---|---|---|---|
| 3 | 盘中 | **1** | 84 | **+0.656** | **1.333** ← 这就是 120c 报的数 |
| 3 | 盘中 | 2 | 59 | +0.054 | 0.136 |
| 3 | 收盘 | 1 | 85 | −0.018 | −0.033 |
| 3 | 收盘 | 2 | 57 | −0.359 | −1.096 |
| 1 | 盘中 | 2 | 171 | −0.117 | −0.538 |
| 1 | 收盘 | 2 | 167 | **+0.161** | **0.745** ← 本报告采用 |

**+0.656 只在「单日只允许 1 只样本构成中位数」时成立**。那种情况下「中位数」= 单只股票的收益，等于拿一只票代表一组 —— 这是伪影，不是信号。加上最低限度的「每组至少 2 只」后立刻塌到 +0.054 / −0.018。

**教训（新增方法论㉜）**：**「按日中位数配对」必须同时约束每组当日最小样本数**，否则中位数退化为单点值，任何差值都能被造出来。

### 4.3 终版结果（全样本 step=1、收盘口径、每组≥2 只、hop=5）

RSI<30 子集（n=20,449，222 个交易日）：

|---|---|---|---|---|---|---|
| S1 收盘不创20日新低 | 167 | +0.161 | 0.74 | 0.75 | 0.74 | 5,380 / 15,069 |
| S2 站上MA5 | 72 | +0.730 | 1.54 | 1.60 | 1.08 | 796 / 19,653 |
| S3 MA5拐头向上 | 37 | +0.998 | 1.99 | **2.19** | **2.11** | 295 / 20,154 |
| S4 当日收阳 | 156 | +0.369 | 1.52 | 1.55 | −0.59 | 4,209 / 16,240 |
| T1 站上MA20 | **0** | — | — | — | — | **0 / 20,449** |
| T2 MA20向上 | **0** | — | — | — | — | **0 / 20,449** |

**裁决**：
- S1（老大最关心的「不创新低」）**差值仅 +0.161pp、t=0.74，连单检验 5% 都不过**
- S2/S3 的 t 值看着像样，但样本从 20,449 砍到 796 / 295，且 t_sub 波动大 → **不足以支撑改模型**
- S4 两口径方向不一致（t_sub = −0.59）→ 不稳
- **T1/T2 样本为 0，不是「效果差」，是「根本不存在这个组合」**

→ **RSI<30 与「站上 MA20」在数学上完全互斥**（20,449 个样本中 0 个）。老大提的「趋势确认」这条前置条件，对低 RSI 反转因子**在定义上就不可能同时满足**。

这不是「效果不好」，是**「要求一个东西同时是冷的和热的」**。任何声称「低 RSI + 趋势确认」双条件的方案，实际筛选结果都是空集。

### 5.5 结论

**真正的问题不是「缺前置条件」，而是「这个映射本身产生不了单调关系」。**

- 加约束 = 在错误的映射上再叠一层筛选，只会让样本更少、结果更不稳
- `+0.656pp` 那个看起来最好的数字，经不起「每组至少 2 只」这一条最基本的要求
- 三个反转因子的分数档**都不单调**，说明「越低 RSI 越高分」这个方向在这个池/这个区间内**没有得到数据支持**

## 6. 调整思路：三个方案的取舍

### 方案 A（保守补丁）：加乘性折扣

```
不创新低 → ×1.0，创新低 → ×0.7
```

- 生益科技效果：`rsi_rev 5.0→3.5`，反转块 `10.00 → 8.50`
- **问题：仍是 8.5 分高位，没有解决问题**
- 样本代价：`RSI<30` 从 20,449 → 5,380（保留 26.3%）
- 收益增量：**+0.161pp，t=0.74，不显著**
- 裁决：**不建议** —— 代价大、收益无、且治不了「跌停股仍显示高分」

### 方案 B（结构性修正）：企稳信号为 0 时该维不计分

```
若 所有企稳信号均为 False → 该维置 None（从分母剔除），
                           而非给 5.0
```

- 生益科技效果：反转块 `10.00 → 5.00`（中性）
- 逻辑：**「没有证据支持反转」≠「反转很强」**。当前代码把「极度超跌」直接等同于「反转在即」，缺一步验证
- 代价：`advice` 需同步 —— `total` 下降后可能掉出 A 级，这是**期望行为**
- 与现有实现的关系：`_weighted_composite()` 已支持「缺失维从分母剔除（禁 or 0）」，**只需把 `None` 传进去**
- 收益增量：本轮数据无法直接证明（因为这是改分数分布，不是加筛选条件），但**逻辑上更诚实**

### 方案 C（根治）：重设映射

三个因子分数档全部不单调、Spearman ≈ 0.02。要么：
- C1 用**分位数**代替绝对阈值（`RSI < 池内 p10` 而非固定 30）
- C2 用**实测分档超额**反推映射（哪个档真的跑赢就给高分）
- C3 若两者都做不出来 → **把 `rsi_rev` 权重降到 0**，与 `oversold60` 同样处理

**必须先确定「反转到底要捕捉什么」**：是「跌深了会弹」（均值回复），还是「跌深且止跌了才会弹」（趋势转折）？当前代码实现的是前者，但老大的质疑本质是想要后者。**而后者在 RSI<30 时不存在**（§4.4）。

## 9. 纪律更新

**㉜ 「按日中位数配对」必须同时约束每组每日最小样本数。**
单日某组只有 1 只时，「中位数」= 单只股票收益，等于拿一只票代表一组，任何差值都能被造出来。实测同一对比：min_grp=1 得 +0.656（t=1.333），min_grp=2 得 +0.054（t=0.136）—— **同一批数据，结论完全相反。**

**㉝ 「加前置条件」前先查两条件的联合分布。**
「RSI<30 且站上MA20」在全样本 495,587 个观测中命中 **0 个**（站上MA20 的最小 RSI = 35.45）。不查联合分布就设计双条件方案，得到的是空集而非弱信号。**「效果不好」和「不存在」是两种完全不同的失败。**

**㉞ 超额收益不能用「均值 − 当日中位数」。**
全池 `raw_mean − daily_median = 1.123pp`，所以任何分档的均值超额都会被整体抬正（实测 15 个档位全为正，+0.43~+1.47）。要算超额就得**同口径相减**（均值对均值、中位对中位），或直接做**配对差**。
