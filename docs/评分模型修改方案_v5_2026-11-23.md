## 二、实证依据（真实面板 IC，323 截面 h20，2025-06-09~2026-09-30）

数据源：`data/val_arrays_h20.npz`（`panel_round124_long` 派生）。因 `score_fund` 覆盖率为 **0.0%**（主力净流入无历史快照，不可回填），故全池有效权重实为 0.80。

### 2.1 缺维规则 × 市值合并 的 IC 与头部超额

| 方案 | IC 均值 | NW t | 头部超额 Q1−Q5 | NW t |
|---|---|---|---|---|
| 现行生产（填 5.0、双维各计） | 0.0628 | 0.70 | −0.052% | −0.10 |
| 缺维剔分母（门控口径） | 0.0630 | 0.71 | 0.023% | 0.06 |
| 缺维按 0 | 0.0607 | 0.78 | −0.064% | −0.20 |
| **填 5.0 + 市值合并取高** | 0.0629 | 0.70 | 0.036% | — |
| **剔分母 + 市值合并取高** | 0.0628 | 0.69 | −0.059% | −0.11 |
| **按 0 + 市值合并取高** | 0.0600 | 0.78 | **+0.164%** | 0.34 |
| 合并取高 + quality 提至 0.15 | 0.0579 | — | **+0.122%** | 0.18 |
| 合并取高 + quality 0.15 + 填 5.0 | 0.0583 | — | −0.065% | −0.14 |

**关键结论：**
1. **市值合并取高对 IC 几乎无损**（0.0630→0.0628），且**头部超额最高的一档正是"按 0 + 合并"**（+0.164%）。这为 M1/M2 的修正方向提供了正面实证支持，而非仅是"逻辑上更合理"。
2. **缺维按 0 与填 5.0 的 IC 差异极小**（0.0607 vs 0.0628，NW t 均 <0.8，远未显著）。此前记忆中的"缺维按 0 会让 IC 从 +0.1520 崩到 +0.0926"是**不同面板/不同口径的历史结论**，在本 323 截面 h20 面板上**未复现**。按 0 是**惩罚性选择**，其依据应是业务逻辑（无数据不应得分），不是"IC 会崩"。
3. **IC 与头部超额方向相反**（quality 提权：IC 0.0630→0.0579 下降，头部超额 0.023%→+0.122% 上升）—— **再次实证印证项目铁律「禁按 IC 排权重」**。因此权重调整必须以**头部超额**为主判据、IC 为辅。
4. **所有方案的 NW t 均不显著**（|t| ≤ 0.78，n=290）。因此**任何权重变更都只能是"先验产品裁决"，禁称经验证的 alpha**（与项目既有披露一致）。

## 三、修改方案（7 项，逐项含参数依据与代价）

### 【P0-A】市值双维互斥取高 —— 修 M1

- **口径**：`score_size = max(score_size_growth, score_dominant)`，合并为**单一维度**，权重 = 0.20 + 0.10 = **0.30**。
- **实现位置**：`ep_size_ind.py` 的 `score_rows`（市值双维赋值唯一实现）——在赋值阶段即取高，只写一个字段。
- **参数依据**：IC 无损（0.0630→0.0628）；头部超额最优档包含合并（+0.164%）；97.3% 样本取值不变。
- **权重守恒**：Σ 仍 = 1.00，total 跨日可比。
- **代价**：单维权重 0.30 触及"单因子 ≤0.20"上限 → 需同步调整 `group_cap`（市值大类本就是 0.30，需核对 group 定义）。

### 【P0-B】缺维规则：结构性不适用 → 剔分母；真实数据缺失 → 按 0 —— 修 M2、M7

- **口径（分层，唯一实现）**：
  - **结构性不适用**（龙头无 size_growth、周期股非周期因子等"该股本就不该有此项"）→ **从分母剔除**。
  - **真实数据缺失**（ep 无覆盖、fund 无覆盖）→ **按 0 计**，不再填 5.0。
  - 判定必须**显式带原因标记**（写 `missing_reason`），禁止用"值恰好为 None"隐式推断。
- **实现位置**：`scale_calc.composite_total`（生产唯一实现）新增 `missing_rule` 参数；`scoring_core.composite_total_matrix` 同步。**门控侧 `factor_validation_core.composite` 必须改为与生产同一口径**（否则 M7 永存）。
- **参数依据**：IC 差异不显著（0.0607 vs 0.0628）⇒ 判据是业务逻辑而非统计；"按 0 + 合并"是头部超额最高档（+0.164%）。
- **代价（必须披露）**：全局按 0 会系统性压低缺数据股。沙盘显示全池中位分 43.16 → 44.82（合并口径下反而略升，因合并已吸收了 size 缺失），但 Top20 重合度仅 15/20 ⇒ **名次会系统性重排，历史 total 跨版本禁比**。

### 【P0-C】成长维接入营收增速 revg —— 修 M3

- **口径**：`score_growth_new = (1−α) × score_growth + α × (revg 申万一级行业内百分位 × 10)`，**α = 0.30**。
- **实现位置**：`growth_factor_b.compute_growth`（成长唯一实现）；revg 取 `fund_split.sub_factors_pit` 已算好的 `revg`（`fund_split.py:330` 现算未用）。
- **参数依据**：
  - revg 数据可得性：全池财务缓存 `data/fin_cache_em/` 的 `营业总收入增长率@20260930` 覆盖 **3058/3624 = 84.4%**，三票实测值与市场一致（亚宝 −2.67%、圣晖 −13.05%、生益 +61.10%）。
  - α 稳健性：α=0.2/0.3/0.4 下 Top20 重合度 13/13/12，**生益稳定第 1**、圣晖名次 12/19/24、航宇 33/33/38、泰金 81/98/116 ⇒ **0.2~0.4 区间结论一致，选中值 0.30**（中性偏保守，避免过度扰动）。
- **代价**：`score_growth` 定义变更 ⇒ 该维历史 IC 序列失效，需重算。

### 【P0-D】业绩超预期 es 给正权重 —— 修 M4

- **口径**：新增 `score_es` 维，权重 **0.05**。分档：超预期 10 / 符合预期 5 / 低于预期 2；**无数据 → 从分母剔除**（禁填 0，避免打压 96.6% 无数据股）。
- **实现位置**：`earnings_surprise.judge_growth_surprise` 已是唯一实现；`enhance_scores.py` 写入 `r['es']` 处同步写 `r['score_es']`；权重表与 `factor_weights.json` 同步。
- **参数依据**：全池 es 覆盖仅 66/1915 = **3.4%**（TOP20 仅生益、三环有）⇒ 权重必须小（0.05）且必须剔分母。
- **瓶颈（历史结论，已作废）**：原 es 预测源为**手工汇总 Excel、非程序化接口**，三季报披露后失效并于 2026-11-26 从项目删除；相关覆盖率与稀疏加分结论不得复用。若要重启 ES，须先接入带 PIT 时间戳的全市场季度预测源（Wind/东财 MCP 等，独立工程）。
- **代价**：es 权重从 0 → 0.05，IC 无损（0.0630 不变，因无数据剔分母）。

### 【P1-E】质量维提权 —— 修 M5

- **口径**：`score_quality` 0.10 → **0.15**；让渡来源：`score_fund` 0.20 → 0.15。
- **参数依据**：**头部超额改善**（0.023% → +0.122%，是本方案中头部表现最好的一档）；IC 下降（0.0630 → 0.0579）但项目铁律已明确 IC 与头部反向、禁按 IC 排权重。
- **代价**：fund 降权后其 0% 覆盖率问题影响面缩小（利好），但 fund 是唯一"消融 t=+4.41 唯一>4"的因子，降权会削弱这一实证支撑 ⇒ **需在门控中重新验证 fund 的边际贡献**。

### 【P1-F】G1 成长门槛实质化 —— 修 M6

- **口径**：`growth_factor_b.anchor_gate` 增加档位：`cagr3 缺失或 ≤0` → 封顶 5.0（现状）；**`0 < cagr3 ≤ 5%` → 封顶 6.0**（新增中间档，惩罚三年零增长但未负的伪成长）。
- **参数依据**：沙盘显示 cagr3≤5% 门槛命中 1372 只（新增命中 97 只），航宇科技（cagr3=0.4%）名次 14 → 41（正确下沉），而圣晖（10.9%）、生益（30.5%）、亚宝（38.5%）不受影响 ⇒ **精准打击"三年近零成长"且不误伤高成长股**。
- **代价**：需确认 5% 阈值的样本外稳健性；当前仅有单面板证据。

### 【P2-G】技术多头排列维（老大此前裁决）—— 附条件

- **原裁决**：释放的 0.10 给多头排列（`tech.bull_level` 0-3 → 0-10 线性映射）。
- **新增证据与建议**：
  1. `step2_stockscorer_v2.py:1215-1218` 记载三重负证据（趋势多头全周期负α、TOP200 池 tech 维 IC −0.035(T+1)/−0.030(T+20)、因子报告"A股是反转市"）。
  2. **映射缺陷**：亚宝药业 bull=2（周线多头）实测 `WMA5−WMA10 = 0.002`（0.029%）—— **贴脸多头**，11-20 周收盘 6.40 若跌到 6.35 即翻空，6.67 分瞬间归零。线性映射把这种脆弱判定直接放大成 0.67 分权重贡献。
  3. **建议**：若保留该维，**必须先加"幅度阈值"过滤**（如 WMA5 至少高出 WMA10 0.5% 以上才计入门档），且**页面须披露"与趋势多头负α实证冲突，属先验产品裁决，未经验证"**。
- **本方案的处理**：**将其列为 P2，排在 P0/P1 之后**，且明确要求先补幅度阈值。若老大要求本轮就上，需接受"分数含一条被关死的实证"这一披露义务。

**Q1｜缺维规则最终形态**（沙盘四档对比，均为 α=0.3 + 市值合并）
